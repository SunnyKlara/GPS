# 01 - 已完成工作详解

## 软件架构

我们采用了 **三层分离架构**，这是嵌入式开发的最佳实践：

```
┌─────────────────────────────────────────────┐
│              应用层 (app/)                    │
│  app_main.c   - 主循环和任务调度             │
│  app_speed.c  - 测速+里程计算               │
│  app_display.c- LED显示管理                  │
│  app_ble_hid.c- BLE HID音乐控制             │
│  app_key.c    - 按键处理                     │
├─────────────────────────────────────────────┤
│              硬件抽象层 (platform/hal.h)      │
│  定义了所有硬件操作的统一接口                │
│  UART / I2C / GPIO / Flash / BLE / System   │
├──────────────────┬──────────────────────────┤
│   PC模拟实现      │    杰理真机实现（待做）   │
│  platform_sim/    │    platform_ac6323a/     │
│  hal_sim.c        │    hal_ac6323a.c         │
│  sim_gui.c        │                          │
└──────────────────┴──────────────────────────┘
```

**为什么这样设计：** 应用层的代码不直接调用任何硬件API，全部通过hal.h的接口。
这样做的好处是——应用层代码在PC上和在真实芯片上，一行都不用改。
拿到杰理SDK后，只需要写一个新的 `hal_ac6323a.c`，实现hal.h里定义的那些函数就行。

## 各模块详细说明

### 1. NMEA协议解析器 (`lib/nmea_parser.c`)

**它做什么：** 
GPS模块（AT6558A）通过UART每秒发送一堆文本，格式叫NMEA-0183协议。
比如：`$GNRMC,083000.00,A,3939.9000,N,11616.4000,E,30.0,45.5,260326,,,A*43`

解析器从这堆文字中提取出：
- 时间（08:30:00 UTC）
- 定位状态（A=有效，V=无效）
- 经纬度（北纬39.665°，东经116.273°）
- 速度（30节 = 55.56 km/h）
- 日期（2026年3月26日）

**工作原理：**
- 状态机逐字节接收：等待`$` → 接收数据并计算XOR校验和 → 等待`*` → 校验2字节hex
- 校验通过后判断语句类型，支持 GNRMC/GPRMC/BDRMC（兼容GPS/北斗/混合模式）
- 解析各字段并存入 `nmea_gps_data_t` 结构体

**测试覆盖：**
- 有效GNRMC语句解析（验证所有字段的数值精度）
- 无效定位状态处理
- 校验和错误拒绝
- GPRMC前缀兼容性
- 共19个断言全部通过

---

### 2. 速度与里程模块 (`app/app_speed.c`)

**测速原理：**
- 从NMEA拿到原始速度（节→km/h换算：乘以1.852）
- 一阶低通滤波：`speed = 0.3 * raw + 0.7 * prev`，防止GPS抖动导致数字跳来跳去
- 低于1km/h自动归零（认为静止），避免原地不动时显示0.3、0.5之类的

**里程原理：**
- 速度×时间的积分：`distance += speed_kmh * dt_hours`
- 每30秒自动保存到Flash（带0xA5A5A5A5魔数标记防误读）
- 支持手动清零

**测试覆盖：**
- 初始状态验证
- 速度更新和滤波收敛
- 突变抑制（60→100km/h滤波效果）
- GPS信号丢失处理
- 最高速度记录和清零
- 共12个断言全部通过

---

### 3. 显示管理模块 (`app/app_display.c`)

**4种显示模式：**
| 模式 | 显示内容 | LED效果示例 |
|------|---------|------------|
| SPEED | 当前速度，1位小数 | `  60.5` |
| MILEAGE | 累计里程，2位小数 | ` 12.34` |
| TIME | 北京时间 HH.MM.SS | `16.30.00` |
| MAX_SPEED | 最高速度 | ` 120.5` |

- 通过长按播放键循环切换模式
- 未定位时显示 `------`（6个横杠）
- 数字转7段码通过查表实现（0x3F=0, 0x06=1 ...）

---

### 4. BLE HID模块 (`app/app_ble_hid.c`)

**原理：** 让AC6323A伪装成蓝牙HID设备（类似蓝牙键盘），发送USB HID Consumer Control键码。
手机操作系统原生支持这些键码，所有音乐APP都能响应，不需要手机端装APP。

**键码映射：**
| 按钮 | HID键码 | 手机行为 |
|------|---------|---------|
| 播放/暂停 | 0xCD | 切换播放/暂停 |
| 下一曲 | 0xB5 | 下一首 |
| 上一曲 | 0xB6 | 上一首 |
| 音量+ | 0xE9 | 增大音量 |
| 音量- | 0xEA | 减小音量 |

**应用层代码已完成，底层BLE发送需要杰理SDK适配。**

---

### 5. 按键处理模块 (`app/app_key.c`)

- 5个物理按键，GPIO轮询检测
- 消抖：连续20ms检测到同一状态才确认
- 支持短按和长按（1.5秒）两种事件
- 通过回调函数通知应用层

**按键分配：**
| 按键 | 短按 | 长按 |
|------|------|------|
| KEY0 | 播放/暂停 | 切换显示模式 |
| KEY1 | 上一曲 | 清零里程 |
| KEY2 | 下一曲 | 清零最高速度 |
| KEY3 | 音量+ | （保留） |
| KEY4 | 音量- | （保留） |

---

### 6. 主应用 (`app/app_main.c`)

- `app_main_init()`: 按顺序初始化所有模块
- `app_main_loop()`: 每次调用执行：
  1. 按键扫描（~10ms周期）
  2. BLE协议栈处理
  3. 显示刷新（每100ms一次）
  4. GPS数据通过UART中断回调自动处理

---

### 7. PC模拟器

**CLI版 (sim_main.c):** 命令行交互，键盘输入模拟按键/GPS/BLE
**GUI版 (sim_gui.c):** Win32窗口，绘制7段数码管、按钮面板、速度滑块

两个版本共用同一套hal_sim.c模拟层和全部应用层代码。
