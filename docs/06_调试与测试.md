## 阶段1：点亮开发板（预计1天）

**目标：** 确认开发环境和烧录工具能用。

**操作步骤：**
1. 安装杰理SDK的编译工具链
2. 编译SDK自带的任意示例工程（比如LED闪烁）
3. 连接开发板，用烧录工具写入固件
4. 观察开发板上的LED是否闪烁
5. 如果SDK支持串口打印，连接USB转TTL，确认能看到printf输出

**验收标准：** 能编译、能烧录、能看到串口打印。

**常见问题：**
- 驱动安装失败 → 检查USB驱动，尝试用管理员权限
- 编译报错 → 检查环境变量和工具链路径
- 烧录失败 → 检查接线，确认波特率，尝试降低烧录速度

## 阶段2：单模块逐个调通（预计3-5天）

### 2.1 UART + GPS模块（第1-2天）

**接线：**
```
ATGM336H TX  →  AC6323A UART_RX引脚
ATGM336H VCC →  3.3V
ATGM336H GND →  GND
GPS天线      →  ATGM336H天线接口
```

**测试代码（临时）：**
```c
// 先不用我们的框架，直接在SDK主函数里测试
void test_gps(void)
{
    // 初始化UART 9600
    uart_init(9600);
    
    while (1) {
        // 读取UART数据并打印到调试串口
        uint8_t buf[256];
        int len = uart_read(buf, sizeof(buf));
        if (len > 0) {
            debug_printf("GPS: %.*s\n", len, buf);
        }
        delay_ms(100);
    }
}
```

**验收标准：**
- 能在调试串口看到 `$GNRMC,...` 格式的NMEA语句
- 到窗户边或室外后，看到状态从 V（无效）变为 A（有效）
- 速度字段出现数值

**然后接入我们的NMEA解析器测试：**
```c
void test_gps_parser(void)
{
    nmea_parser_init();
    uart_init(9600);
    
    while (1) {
        uint8_t buf[256];
        int len = uart_read(buf, sizeof(buf));
        for (int i = 0; i < len; i++) {
            if (nmea_parser_feed(buf[i])) {
                const nmea_gps_data_t *gps = nmea_parser_get_data();
                debug_printf("Speed: %.1f km/h, Valid: %d, Time: %02d:%02d:%02d\n",
                    gps->speed_kmh, gps->is_valid,
                    gps->hour, gps->minute, gps->second);
            }
        }
        delay_ms(10);
    }
}
```

### 2.2 I2C + LED显示（第2-3天）

**接线：**
```
AC6323A SCL引脚 → TM5020A SCL (加4.7K上拉到3.3V)
AC6323A SDA引脚 → TM5020A SDA (加4.7K上拉到3.3V)
TM5020A VCC → 3.3V
TM5020A GND → GND
数码管 → TM5020A的段选/位选引脚
```

**测试步骤：**
1. 先用逻辑分析仪确认I2C波形是否正确（SCL有时钟、SDA有数据）
2. 发送全亮命令，看数码管是否全亮
3. 发送数字"123456"，看显示是否正确
4. 测试小数点显示

**如果I2C不通的排查步骤：**
```
1. 用万用表量SCL/SDA空闲时是否为高电平（3.3V）
   → 不是 → 检查上拉电阻
2. 用逻辑分析仪看SCL是否有时钟波形
   → 没有 → I2C初始化有问题，检查引脚配置
3. SCL有时钟但SDA没有ACK
   → I2C地址错误，尝试其他地址（0x48, 0x44, 0x68...）
4. 用I2C扫描程序遍历所有地址
```

### 2.3 GPIO + 按键（第3天）

**接线：** 5个按键，一端接GPIO引脚，一端接GND。

**测试：**
```c
void test_keys(void)
{
    gpio_init();  // 配置为输入上拉
    
    while (1) {
        for (int i = 0; i < 5; i++) {
            if (gpio_read(key_pin[i]) == 0) {  // 按下=低电平
                debug_printf("Key %d pressed\n", i);
            }
        }
        delay_ms(50);
    }
}
```

**验收：** 按每个键都能看到对应的打印输出，松开后停止。

### 2.4 BLE广播测试（第3-4天）

**目标：** 手机能搜到设备名"GPS-Speedometer"

**步骤：**
1. 在SDK的BLE初始化代码中设置设备名
2. 启动BLE广播
3. 手机上打开 nRF Connect APP
4. 搜索，应能看到 "GPS-Speedometer"
5. 点击连接，查看GATT服务列表

**验收：** 手机能搜到并连接。

### 2.5 BLE HID按键测试（第4-5天）

**目标：** 连接手机后，发送按键能控制音乐。

**步骤：**
1. 配置HID Report Descriptor（见05文档）
2. 手机连接设备
3. 手机上打开任意音乐APP播放
4. 芯片发送 Play/Pause 键码
5. 观察音乐是否暂停/恢复

**验收：** 5个按键全部能控制手机音乐。

## 阶段3：功能联调（预计2-3天）

把所有模块接入我们的框架，用完整的 `app_main_init()` + `app_main_loop()` 运行。

**测试清单：**

| 测试项 | 方法 | 预期结果 |
|--------|------|---------|
| 启动流程 | 上电，观察串口日志 | 打印初始化信息，LED显示 "------" |
| GPS定位 | 放到窗边/室外 | 30-60秒后LED显示速度数值 |
| 速度显示 | 坐车/骑车移动 | LED显示实时速度 |
| 模式切换 | 长按播放键 | LED依次显示：速度→里程→时间→最高速度 |
| 时间显示 | 切到时间模式 | 显示当前北京时间 |
| 里程累计 | 移动一段距离 | 里程数字增加 |
| 掉电保存 | 移动后断电重启 | 里程数据仍在 |
| 里程清零 | 长按上一曲键 | 里程归零 |
| BLE连接 | 手机蓝牙连接 | 串口打印"已连接" |
| 音乐控制 | 按5个按键 | 手机音乐响应对应操作 |
| BLE断开 | 手机关蓝牙 | 串口打印"已断开"，按键无反应 |
| 无GPS信号 | 在室内深处 | LED显示 "------"，不崩溃 |
| 高速测试 | 坐高速公路的车 | 速度显示准确（对比手机GPS） |

## 阶段4：整机测试（预计2天）

### 稳定性测试
- 连续运行24小时不重启、不死机
- BLE反复连接/断开50次不异常
- GPS信号丢失/恢复100次不异常

### 精度测试
- 对比手机GPS速度，误差应在±3km/h以内
- 里程对比手机导航里程，误差应在±5%以内
- 时间对比标准时间，误差应在±1秒以内

### 户外路测
- 骑车/开车实际使用
- 测试不同速度范围：步行(5km/h)、骑车(20km/h)、城市驾驶(60km/h)、高速(120km/h)
- 测试GPS冷启动和热启动时间

### 兼容性测试
- iPhone (iOS 14+)
- 至少3款不同品牌Android手机
- 测试网易云、QQ音乐、酷狗3个APP
