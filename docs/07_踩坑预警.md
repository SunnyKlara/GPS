# 07 - 踩坑预警（可能出问题的地方）

## 按风险等级排列（从高到低）

---

## 🔴 高风险：BLE HID兼容性问题

**问题描述：** 不同手机对BLE HID的支持程度不一样，可能出现：
- iOS能用但Android不行（或反过来）
- 能连接但按键不响应
- 连接几分钟后自动断开
- 一些国产手机ROM裁掉了BLE HID支持

**预防措施：**
1. 严格按USB HID标准写Report Descriptor，不要自创格式
2. 先用nRF Connect验证GATT服务结构正确
3. iOS要求加密配对（Security Level 2），不能跳过
4. Report发送后必须发释放（全0），否则手机以为一直按着
5. BLE连接参数不要太激进，建议连接间隔30-50ms

**遇到问题时的排查步骤：**
```
手机搜不到？ → 检查广播数据和广播状态
搜到连不上？ → 检查配对流程，iOS需要加密
连上没反应？ → 用nRF Connect检查HID Service是否注册正确
有时好有时坏？ → 检查连接参数，可能是连接超时
```

## 🔴 高风险：杰理SDK学习曲线

**问题描述：** 
杰理的SDK文档不如Nordic/ESP32那么完善，很多东西需要看示例代码推断。
编译环境也是私有的（pi32编译器），不是常见的GCC/ARM-CC。

**预防措施：**
1. 买开发板时找能提供技术支持的卖家
2. 加杰理开发者QQ群/微信群（代理商通常会拉你进群）
3. 从SDK的demo工程开始改，不要从零开始写
4. 保留SDK原始工程不动，在副本上修改
5. 遇到编译报错先搜群聊记录

**常见SDK问题：**
- 编译器路径没配对 → 检查Makefile里的TOOLS_PATH
- 链接错误 → 检查lib/目录下的.a文件是否完整
- 烧录后不启动 → 检查时钟配置和启动模式

## 🟡 中风险：GPS精度和首次定位时间

**问题描述：**
- 冷启动可能需要30-60秒，用户开机后看着 "------" 会以为坏了
- 城市中高楼遮挡会导致信号不好，速度跳变
- 低速（<5km/h）时GPS精度差，速度可能在0-3km/h之间跳

**预防措施：**
1. ✅ 已实现低通滤波（alpha=0.3），抑制速度跳变
2. ✅ 已实现低速归零（<1km/h视为静止）
3. 可以在定位前显示 "GPS..." 而不是 "------"，让用户知道在搜星
4. 如果AT6558A支持热启动/辅助定位(AGPS)，可以加速首次定位
5. 可以在config.h中调整滤波参数来适应不同使用场景

**GPS天线放置要求：**
- 必须朝天（放在车把上而不是口袋里）
- 不能被金属壳体完全包裹
- 尽量远离2.4GHz蓝牙天线（间距>2cm）

## 🟡 中风险：Flash擦写寿命

**问题描述：** 芯片内部Flash通常有10万次擦写寿命。如果里程每秒存一次，
10万秒≈28小时就用完了。

**预防措施：**
1. ✅ 已设计30秒保存一次（10万×30秒≈35天连续运行）
2. 可以进一步优化：只在速度归零（停车）时保存
3. 杰理SDK如果提供VM（虚拟存储器），它会自动做磨损均衡
4. 如果需要更长寿命，可以增大保存间隔到5分钟

---

## 🟡 中风险：TM5020A资料不全

**问题描述：** TM5020A可能不是特别常用的芯片，数据手册可能不好找。

**预防措施：**
1. 先确认能拿到完整数据手册（I2C协议、寄存器表、时序图）
2. 如果拿不到，果断换成 TM1637 或 MAX7219，这两个资料和代码满大街都是
3. 换驱动芯片只影响I2C通信的数据格式，应用层完全不受影响

**推荐替代方案优先级：**
```
首选: TM1637 (4位版最便宜最多资料) 或 TM1638 (8位版)
次选: MAX7219 (SPI接口, 8位, 驱动能力强)
备选: HT16K33 (I2C接口, 16段×8位)
```

---

## 🟢 低风险：多任务冲突

**问题描述：** 
AC6323A资源有限（RAM约8-16KB），BLE协议栈本身就占不少。
同时跑GPS解析+显示刷新+按键扫描+BLE通信，可能有资源竞争。

**预防措施：**
1. 我们的代码已经设计为非阻塞轮询模式，不需要RTOS
2. GPS数据在UART中断中解析，不占主循环时间
3. 显示刷新100ms一次，BLE处理由协议栈管理
4. 如果RAM不够，可以减小NMEA缓冲区（当前256字节，可减到128字节）

---

## 🟢 低风险：功耗问题

**问题描述：** 如果用电池供电，GPS模块持续工作比较耗电（25mA）。

**预防措施：**
1. USB供电/车载供电不需要担心功耗
2. 如果用电池，可以实现GPS间歇模式（开5秒/关25秒，静止时）
3. BLE广播间隔可以加大（1秒），降低蓝牙功耗
4. LED亮度可调（通过TM5020A的亮度寄存器），降低显示功耗

## 常见错误清单（开发中容易犯的）

| 错误 | 后果 | 正确做法 |
|------|------|---------|
| GPS TX/RX接反 | 收不到GPS数据 | TX→RX，RX→TX（交叉连接） |
| I2C没加上拉电阻 | 通信不稳定或完全不通 | SCL/SDA各加4.7K上拉到VCC |
| BLE HID按键发了不释放 | 手机以为一直按着，音量疯涨 | 每次按键后必须发0x00释放 |
| Flash地址写错 | 数据丢失或覆盖固件 | 用SDK提供的VM接口，不要直接写Flash |
| GPS天线朝下放 | 搜不到星 | 天线朝天放置 |
| 没等GPS定位就计算里程 | 里程不准 | 检查is_valid标志 |
| 速度单位搞混 | 节(knot)和km/h差1.852倍 | 确认换算公式 |
| BLE广播数据太长 | 手机搜不到 | 广播数据不超过31字节 |
