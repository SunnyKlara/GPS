# 11 - 原理图详细分析（AC6323A-Z 测试板 20260330）

> 基于原理图PDF截图逐模块分析，对照SDK代码和现有项目代码

---

## 一、总体架构

原理图包含以下主要模块：
1. **AC6323A4 主控** — 杰理蓝牙SoC（U1）
2. **AT6558R-5N32 GPS模块** — 中科微多星座定位（U6）
3. **LED驱动芯片** — HT1633/CM4718（U3，非之前假设的TM5020A）
4. **7段LED数码管阵列** — 大量LED段（SEG0~SEG10 × GRID1~GRID7）
5. **ADC按键** — 电阻分压式多按键（单IO口）
6. **充电管理** — TP4056 + 锂电池
7. **电源** — IP6808A 升压 + AT2659 LDO 3.3V

右侧引脚（从原理图）：
- Pin 19(PB4) → TX（经220R电阻R6）
- Pin 18(PB5) → RX（经220R电阻R7）
- Pin 17(PB6) → TX1（经220R电阻R8）
- Pin 16(PB7) → RX1（经220R电阻R9）

- Pin 20(SW) → SW调试

### 关键发现：

1. **LED驱动不是I2C，是三线串行接口（DIO/CLK/STB）**
   - PA0 → DIO（数据线）
   - PA1 → STB（锁存/片选）
   - PA2 → CLK（时钟线）✅ 已确认

2. **GPS连接用了两组UART**
   - PB4(TX)/PB5(RX) → GPS主串口 TX/RX
   - PB6(TX1)/PB7(RX1) → GPS辅助串口 TX1/RX1
   - 都经过220Ω串联电阻保护

3. **按键是ADC方式，不是独立GPIO**
   - PA8 → ADC_KEY（单根线，电阻分压识别多个按键）
   - 这和SDK默认配置一致（TCFG_ADKEY_ENABLE）

4. **PA7 → ON_OFF**（开关机按键）

### 上拉电阻：
- DIO/CLK/STB 各有 **10K上拉到VDDIO**（R10/R11/R12/R13）
- 信号线经 **220R串联电阻**（R15/R16/R17）保护

### HT1633芯片旁边标注：
- **HT1633_CM4718** — 说明是HT1633兼容芯片CM4718

- **SEG0~SEG10**（11条段选线）
- **GRID1~GRID7**（7条位选线）
- 最大可驱动 11×7 = **77个LED段**

## 五、LED数码管排布分析

### 数码管构成方式：
每个"数码管"不是成品模块，而是用 **7颗独立LED** 排列成"8"字形。这就是为什么PCB上有大量独立LED焊盘（A1~A70+）。

### 显示布局（已确认）：

```
┌─────────────────────────────────────────────────┐
│                                                   │
│   ██   ██       ██   ██       ██                 │
│   ██   ██   :   ██   ██   :   ██                 │
│   ██   ██       ██   ██       ██                 │
│  GRID1 GRID2   GRID3 GRID4   GRID5               │
│   时十  时个     分十  分个     秒个               │
│                                                   │
│   ██   ██       ██   ██   .                      │
│   ██   ██   :   ██   ██                          │
│   ██   ██       ██   ██                          │
│  GRID6 GRID7   (GRID扩展)                        │
│  里程           里程                              │
│                                                   │
└─────────────────────────────────────────────────┘

上排: 00:00:0  → 时:分:秒（5位 + 2个冒号指示灯）
下排: 00:00.   → 里程（4位 + 冒号 + 小数点指示灯）
```

### LED与HT1633的映射关系：
- 每个数码管位对应一个 **GRID**（位选）
- 每个LED段(a~g)对应一个 **SEG**（段选）
- 冒号和小数点也各占SEG×GRID交叉点
- 总共 **70颗LED**：9位×7段 + 3冒号×2 + 1小数点 = 63+6+1 = 70

### SEG段与7段对应关系（需要实测确认）：
```
    aaaa        SEG?
   f    b       每个段对应哪个SEG
   f    b       需要点亮单个LED逐个确认
    gggg        或者从原理图追线确认
   e    c
   e    c
    dddd   dp
```

具体哪个SEG对应哪个段(a~g)，需要在实际硬件上逐个点亮测试，或者从原理图中追踪每个LED焊盘(A1~A70)连接到U3的哪个SEG和GRID引脚。

## 六、按键电路分析

从原理图和PCB实物照片确认：

### ADC按键方案：
- 单根ADC线（PA8/ADC_KEY）
- 多个按键通过不同阻值的电阻分压
- 按下不同按键产生不同的ADC电压值
- SDK通过ADC采样值判断哪个按键被按下

### 按键数量和功能（从PCB丝印确认，共8个）：

| 按键序号 | PCB丝印 | 功能 | HID用途 |
|---------|---------|------|---------|
| 0 | POWER | 开关机 | 系统电源控制 |
| 1 | PLAY | 播放/暂停 | HID Consumer: Play/Pause (0xCD) |
| 2 | VOL- | 音量减 | HID Consumer: Volume Down (0xEA) |
| 3 | VOL+ | 音量加 | HID Consumer: Volume Up (0xE9) |
| 4 | 电话 | 接听/挂断电话 | HID Telephony: Hook Switch |
| 5 | MODE | 模式切换 | 切换显示模式（速度/里程/时间） |
| 6 | PREV | 上一曲 | HID Consumer: Scan Prev Track (0xB6) |
| 7 | NEXT | 下一曲 | HID Consumer: Scan Next Track (0xB5) |

### 按键电路详细分析（从原理图放大图确认）：

**上拉电阻**：R21 = **22K**，上拉到VDDIO
**滤波电容**：C1 = 102（1nF）
**按键数量**：8个，全部通过ADC分压连接到ADC_KEY(PA8)

**原理图中可识别的电阻值**：10K、15K、20K、100K（1%精度）
8个按键各用不同阻值的电阻分压，产生8个不同的ADC电压等级。

**实际按键功能（以PCB丝印为准）**：
POWER / PLAY / VOL- / VOL+ / 电话 / MODE / PREV / NEXT

**SDK配置方法**：
ADC按键的阈值不需要手算，最可靠的方式是：
1. 烧一个测试固件，逐个按键打印ADC原始值
2. 把实测的8个ADC值填到 `board_ac6323a_demo_cfg.h` 的阈值表
3. SDK的ADC按键驱动会自动处理消抖和识别

**SDK需要修改的配置**：
```c
#define TCFG_ADKEY_ENABLE       ENABLE_THIS_MOUDLE
#define TCFG_ADKEY_PORT         IO_PORTA_08        // 改为PA8
#define TCFG_ADKEY_AD_CHANNEL   AD_CH_PA8          // 对应ADC通道
#define TCFG_ADKEY_EXTERN_UP_ENABLE  ENABLE_THIS_MOUDLE  // 外部22K上拉
#define R_UP  220   // 22K外部上拉（SDK中220代表22K）
#define KEY_NUM  8  // 改为8个按键
```

### 关键发现：
- **按键方案是ADC分压式，不是独立GPIO**
- 只占用一个IO口（PA8），非常节省引脚
- 一共8个按键，比之前假设的5个多了POWER、电话、MODE
- SDK已经有完整的ADC按键驱动框架，最多支持10个
- 需要修改SDK配置中的ADC引脚从PA1改为PA8
- KEY_NUM需要从3改为8
- **电话按键**是新增需求：BLE HID接听/挂断电话功能

## 七、电源系统分析

### 充电部分（右上角"充电灯"区域）：
- **TP4056**（或兼容芯片）— 锂电池充电管理
- USB 5V输入 → TP4056 → 4.2V锂电池
- 充电指示LED

### 升压部分：
- **IP6808A** — 升压芯片
- 输入：锂电池电压（3.0~4.2V）
- 输出：可能是5V或其他电压给LED驱动

### LDO部分：
- **AT2659** — 3.3V LDO
- 给GPS模块(AT6558R)和AC6323A的VDDIO供电

### 供电路径：
```
USB 5V → TP4056 → 锂电池(4.2V) → AC6323A VBAT(经肖特基二极管)
                                  → IP6808A升压 → LED驱动VDD
                                  → AT2659 LDO → 3.3V → GPS模块
                                                       → AC6323A VDDIO
```

## 九、需要重写/大改的模块

### 1. LED驱动层（最大改动）

之前的 `hal_i2c_write()` 方式完全不适用了。需要：

- **新增 HT1633 驱动**：实现三线串行协议（DIO/CLK/STB）
- HT1633 通信协议：
  - STB拉低开始通信
  - CLK上升沿采样DIO数据
  - 命令格式：`100` + 8位命令 + 不关心位
  - 数据写入：`101` + 6位地址 + N×4位数据（自动递增）
  - STB拉高结束通信
- 需要重新定义段码映射（SEG和GRID的对应关系）

### 2. 显示模块（app_display.c）

- 段码表可能需要调整（取决于PCB上LED段的物理连线）
- 显示位数从6位改为实际位数
- `hal_i2c_write()` 改为 `hal_ht1633_write()` 或类似接口

### 3. 按键模块（app_key.c）

- 之前的GPIO扫描方式不适用
- 直接使用SDK的ADC按键框架（已经很完善）
- 只需要修改SDK配置中的ADC引脚和电阻值

### 4. HAL层（hal_ac6323a.c）

- 删除I2C相关实现
- 新增HT1633三线串行驱动
- 修改GPIO引脚定义
- 修改UART引脚（PB4/PB5 或 PB6/PB7）

## 十一、SDK配置需要修改的地方

### board_ac6323a_demo_cfg.h 需要改的配置：

```c
// 1. UART0 调试串口 — 保持不变（PA0做调试口会冲突，需要换引脚或禁用）
// ⚠️ 注意：PA0已经被LED驱动DIO占用！
// SDK默认 TCFG_UART0_TX_PORT = IO_PORTA_00 会冲突！
// 需要改为其他引脚或禁用调试串口
#define TCFG_UART0_TX_PORT    NO_CONFIG_PORT  // 或换到其他空闲引脚

// 2. ADC按键引脚修改
#define TCFG_ADKEY_PORT       IO_PORTA_08     // 原来是PA1，改为PA8
#define TCFG_ADKEY_AD_CHANNEL AD_CH_PA8       // 对应ADC通道

// 3. I2C配置 — 可以禁用（不再需要）
// 软件IIC和硬件IIC配置可以保留但不使用

// 4. 需要新增GPS UART配置
// 使用UART1接收GPS数据
```

### 重要冲突：
- **PA0** 在SDK默认配置中是 UART0_TX（调试串口），但原理图中PA0连接到LED驱动的DIO
- **PA1** 在SDK默认配置中是 ADKEY端口，但原理图中PA1连接到LED驱动的STB
- 这两个冲突必须解决：要么禁用调试串口，要么把调试串口改到USB口

## 十二、下一步开发建议

### 优先级排序：

1. **写HT1633驱动** — 替换原来的I2C驱动，实现三线串行协议（PA0/PA1/PA2）
2. **确认LED段码映射** — 需要在硬件上逐个点亮LED，确认每个SEG对应数码管的哪个段(a~g)

4. **配置GPS UART** — 用PB5(RX)接收GPS数据
