## 三、LED驱动芯片协议（TM1638兼容）

### 这是最关键的改动——之前代码假设I2C，实际是TM1638三线串行协议

### 3.1 通信时序
```
STB ‾‾‾\_____________________________/‾‾‾
CLK ‾‾‾‾\_/‾\_/‾\_/‾\_/‾\_/‾\_/‾\_/‾\_/‾‾
DIO ----<D0><D1><D2><D3><D4><D5><D6><D7>--
         LSB first, CLK上升沿采样DIO
```

- STB拉低 → 开始通信
- 数据在CLK上升沿被采样
- LSB先发（低位在前）
- STB拉高 → 结束通信

### 3.2 命令格式

| 命令 | 字节 | 功能 |
|------|------|------|
| 0x40 | 数据命令 | 写显示数据，地址自动递增模式 |
| 0x44 | 数据命令 | 写显示数据，固定地址模式 |
| 0x42 | 数据命令 | 读按键数据 |
| 0xC0~0xCF | 地址命令 | 设置显示RAM起始地址(0x00~0x0F) |
| 0x80 | 显示控制 | 关闭显示 |
| 0x88~0x8F | 显示控制 | 开启显示，亮度0~7级 |

### 3.3 写显示数据流程（自动递增模式）
```c
// 1. 发送数据命令：自动递增
STB = LOW;
shiftOut(0x40);      // 命令：写数据，地址自增
STB = HIGH;

// 2. 发送地址 + 数据
STB = LOW;
shiftOut(0xC0);      // 起始地址 0x00
shiftOut(seg_data[0]); // 地址0x00: GRID1的SEG数据
shiftOut(0x00);        // 地址0x01: GRID1的扩展（如果有LED指示灯）
shiftOut(seg_data[1]); // 地址0x02: GRID2的SEG数据
shiftOut(0x00);        // 地址0x03: GRID2的扩展
// ... 每个GRID占2个字节，共16字节
STB = HIGH;

// 3. 开启显示
STB = LOW;
shiftOut(0x8F);      // 显示ON，最大亮度
STB = HIGH;
```

### 3.4 显示RAM布局（TM1638标准）
```
地址  内容
0x00  GRID1 低8位 (SEG1~SEG8)
0x01  GRID1 高2位 (SEG9~SEG10)
0x02  GRID2 低8位
0x03  GRID2 高2位
0x04  GRID3 低8位
0x05  GRID3 高2位
...
0x0E  GRID8 低8位
0x0F  GRID8 高2位
```

每个GRID对应一位数码管，低8位的每个bit对应一个SEG（即一个LED段）。

### 3.5 段码表（标准7段，和之前代码一致）
```
    SEG_A
   ------
  |      |
SEG_F  SEG_B
  |      |
   ------   ← SEG_G
  |      |
SEG_E  SEG_C
  |      |
   ------   . SEG_DP
    SEG_D

数字段码（假设 bit0=SEG_A, bit1=SEG_B, ... bit6=SEG_G, bit7=SEG_DP）：
0=0x3F  1=0x06  2=0x5B  3=0x4F  4=0x66
5=0x6D  6=0x7D  7=0x07  8=0x7F  9=0x6F
```

⚠️ **注意**：具体哪个bit对应哪个段(a~g)取决于PCB走线。
上面是标准映射，实际可能不同，需要上机逐段点亮测试确认。

## 四、显示布局

```
上排（时间）:  [D1] [D2] :[冒号1] [D3] [D4] :[冒号2] [D5]
               时十  时个          分十  分个           秒个
               7LED  7LED  2LED   7LED  7LED   2LED   7LED
                                                        = 46颗

下排（里程）:  [D6] [D7] :[冒号3] [D8] [D9] .[小数点]
               千    百           十    个
               7LED  7LED  2LED  7LED  7LED   1LED
                                                        = 24颗
```

### LED统计（总计70颗）：
| 区域 | 内容 | 数量 |
|------|------|------|
| 上排5位数字 | 时十、时个、分十、分个、秒个 | 5×7 = 35 |
| 上排2个冒号 | 时:分、分:秒 | 2×2 = 4 |
| 下排4位数字 | 千、百、十、个 | 4×7 = 28 |
| 下排1个冒号 | 百:十 分隔 | 1×2 = 2 |
| 下排1个小数点 | 个位后 | 1 |
| **总计** | | **70颗** |

### CM4718驱动能力：
- SEG0~SEG10（11条段选）× GRID1~GRID7（7条位选）= 77个交叉点
- 70颗LED < 77，完全够用
- 剩余7个交叉点空置

### GRID分配（推测，需实测确认）：
```
GRID1 → 上排D1(时十) 的7段 + 冒号1上点?
GRID2 → 上排D2(时个) 的7段 + 冒号1下点?
GRID3 → 上排D3(分十) 的7段 + 冒号2上点?
GRID4 → 上排D4(分个) 的7段 + 冒号2下点?
GRID5 → 上排D5(秒个) 的7段
GRID6 → 下排D6(千)   的7段 + 冒号3上点?
GRID7 → 下排D7(百)   的7段 + 冒号3下点?
```
下排D8(十)和D9(个)可能复用GRID5~GRID7的高位SEG，
或者用SEG8~SEG10扩展。具体映射需要实测。

## 五、按键方案

### 电路结构
```
VDDIO ─── R21(22K) ─┬─ ADC_KEY(PA8)
                     │
                     ├── C1(1nF) ─── GND  (滤波)
                     │
                     ├── K5(POWER?) ── R(阻值1) ── GND
                     ├── K6(PLAY?)  ── R(阻值2) ── GND
                     ├── K9(VOL-?)  ── R(阻值3) ── GND
                     ├── K10(VOL+?) ── R(阻值4) ── GND
                     ├── K2(电话?)  ── R(阻值5) ── GND
                     ├── K3(MODE?)  ── R(阻值6) ── GND
                     ├── K4(PREV?)  ── R(阻值7) ── GND
                     └── K7(NEXT?)  ── R(阻值8) ── GND
```

### 电阻值（从原理图读取）：10K, 15K, 20K, 100K（各有使用）

### 开发策略
SDK的ADC按键框架已经非常成熟，配置步骤：
1. 修改 `TCFG_ADKEY_PORT` 为 `IO_PORTA_08`
2. 修改 `TCFG_ADKEY_AD_CHANNEL` 为 `AD_CH_PA8`
3. 修改 `R_UP` 为 220（代表22K）
4. 烧测试固件，逐个按键打印ADC原始值
5. 把实测值填入 `TCFG_ADKEY_ADx` 阈值表
6. 修改 `KEY_NUM` 为 8

| KEY0 | POWER | 开机 | 关机 |
| KEY1 | PLAY | BLE: 播放/暂停 | — |

| 功能 | HID Usage Code | TM1638兼容位域 |
|------|---------------|---------------|
| 播放/暂停 | 0xCD | CONSUMER_PLAY_PAUSE (0x0004) |

| 下一曲 | 0xB5 | CONSUMER_SCAN_NEXT_TRACK (0x0020) |
| 音量+ | 0xE9 | CONSUMER_VOLUME_INC (0x0001) |
| 音量- | 0xEA | CONSUMER_VOLUME_DEC (0x0002) |
