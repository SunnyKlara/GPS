# GPS测速仪 - 软件开发答辩准备

## 一、项目概述（30秒版本）

这是一个基于杰理AC6323A蓝牙芯片的GPS测速仪。功能包括：GPS实时测速和时间显示、累计里程、蓝牙遥控手机音乐、8个按键控制。显示用9位LED数码管，驱动芯片是CM4718（TM1638兼容）。

软件基于杰理官方蓝牙HID SDK开发，我把GPS测速仪的功能代码以模块化方式嫁接到SDK框架上。

---

## 二、"你是怎么做的？" — 开发流程

### 第一步：分析硬件
拿到板子和原理图后，先梳理清楚硬件连接关系：
- 主控AC6323A → LED驱动CM4718：三线串行（PA0/PA1/PA2）
- 主控 → GPS模块AT6558R：UART（PB5接收，9600bps）
- 8个按键 → ADC分压到PA8

### 第二步：搭建开发环境
用杰理提供的Code::Blocks + 专用编译器（clang for q32s），配合烧录工具。SDK选的是HID键盘例程作为基础，因为我们的蓝牙功能就是HID遥控。

### 第三步：先调通显示
LED驱动是最直观的——能看到东西就知道代码跑起来了。先写TM1638协议的GPIO位操作，全亮70颗LED验证通信正常，然后逐段点亮确认段码映射。

### 第四步：标定按键
写了一个专门的标定固件，按每个键时在数码管上实时显示ADC原始值，记录下来填入阈值表。

### 第五步：实现蓝牙HID
基于SDK的HOGP框架，把按键事件映射到HID Consumer Control键码（播放暂停、音量、切歌），连手机实测验证。

### 第六步：写GPS接收和解析
UART中断接收GPS数据，NMEA状态机解析$GNRMC语句，提取时间和速度，低通滤波后显示。

### 第七步：集成和完善
里程积分、掉电保存、MODE键电话状态机、蓝牙连接指示灯，逐个功能加上去测试。

## 三、"碰到什么头痛的问题？" — 踩坑经历

### 坑1：CM4718只有7个GRID（最头痛的）

**现象**：按TM1638的标准写16字节数据，第一个数码管显示异常。

**排查过程**：一开始以为是段码表算错了，反复检查代码没问题。后来试着只写14字节，第一个数码管就正常了。这才意识到CM4718虽然兼容TM1638协议，但RAM只有14字节（7个GRID），写第15-16字节时地址回绕到0x00，把GRID1的数据覆盖了。

**解决**：所有写入操作限制为14字节。这个坑在CM4718的datasheet上没有明确说明，完全靠实测发现的。

### 坑2：段码映射和原理图对不上

**现象**：按标准7段数码管的段码表（bit0=a, bit1=b...）写数字，显示出来是乱的。

**原因**：PCB走线决定了GRID和段的对应关系，不是标准顺序。实际是GRID1=a, GRID2=f, GRID3=b, GRID4=g, GRID5=e, GRID6=c, GRID7=d。

**解决**：写了逐段点亮的测试固件，每次只亮一个GRID看哪个段亮了，一个一个确认映射关系，然后重新算段码表。

### 坑3：蓝牙音量键不灵敏

**现象**：上下曲切歌正常，但音量加减按了经常没反应。

**原因**：HID报告的按下和释放发得太快，两个报告之间几乎没有间隔，手机来不及处理。

**解决**：在按下报告和释放报告之间加了50ms延时（os_time_dly(5)），手机就能可靠识别了。

### 坑4：杰理编译器只支持C89

**现象**：编译报错，提示变量声明位置不对。

**原因**：杰理的clang编译器配置为C89标准，不允许在代码块中间声明变量，必须在函数或块的开头声明。

**解决**：所有变量声明移到函数开头。写代码时养成习惯，先声明后使用。

### 坑5：BLE连接状态检测不到

**现象**：蓝牙连上了但小数点指示灯还在闪烁（应该常亮）。

**原因**：一开始用SDK的蓝牙事件回调（BT_STATUS_FIRST_CONNECTED）来检测连接状态，但BLE的连接事件走的是HOGP模块的内部回调，不经过这个事件。

**解决**：改为在100ms定时循环里直接轮询 `ble_hid_is_connected()` 函数，返回非零就是已连接。简单可靠。

## 四、"这个功能是怎么实现的？" — 技术细节

### LED显示怎么驱动的？

CM4718用三线串行协议（类似SPI但不是标准SPI）。PA0是数据线，PA1是片选，PA2是时钟。数据在时钟上升沿被采样，低位先发。

写显示的流程：
1. 发命令0x40（自动递增模式）
2. 发地址0xC0（从地址0开始）
3. 连续写14字节数据（7个GRID × 2字节）
4. 发命令0x8F（开启显示，最大亮度）

每个GRID占2字节，低字节的8个bit对应SEG1~SEG8（8个数码管），高字节的bit0对应SEG9（第9个数码管），bit1对应SEG10（冒号/小数点）。

### 8个按键怎么只用一个IO口？

ADC分压原理。8个按键通过不同阻值的电阻接地，上面有22K上拉到电源。没按键时ADC读到最大值（约1023），按不同的键分压不同，ADC值不同。比如NEXT键直接接地所以ADC=0，POWER键电阻最大所以ADC=840。

SDK的ADC按键驱动每10ms采样一次，连续几次读到同一个范围内的值就判定为按键按下，实现消抖。

### 蓝牙怎么控制手机音乐的？

用BLE HID协议。设备端定义一个Report Map（类似USB HID的描述符），告诉手机"我能发Consumer Control类型的按键"。Report Map里列了8个Usage：音量加、音量减、播放暂停、静音、上一曲、下一曲、快进、快退。

按键时发一个2字节的位域报告，比如播放暂停是bit2=1即0x0004，音量加是bit0=1即0x0001。发完按下报告后延时50ms再发全零的释放报告。

### GPS数据怎么解析的？

GPS模块每秒输出多条NMEA语句，我只关心$GNRMC这一条，它包含时间、定位状态、速度。

解析用状态机：
- 等待`$`字符 → 进入接收状态
- 逐字节接收，同时XOR计算校验和
- 遇到`*` → 读取2字节十六进制校验和
- 校验通过 → 按逗号分隔提取字段

速度字段单位是"节"（海里/小时），乘以1.852转成km/h。时间是UTC，加8小时转北京时间。

### 里程怎么算的？

数学上就是速度对时间的积分。离散化后：每100ms执行一次 `里程 += 速度(km/h) × 0.1秒 / 3600`。速度低于1km/h时不累加，避免GPS噪声导致静止时里程增长。

### 里程掉电怎么不丢？

用SDK的VM（Virtual Memory）系统。本质是在Flash上划了一块区域做键值存储，SDK内部做了磨损均衡。每30秒检查一次，如果里程有变化就写入Flash。开机时读取恢复。数据结构带一个0xA55A的magic头，读取时先验证，防止读到未初始化的垃圾数据。

## 五、"代码结构是怎样的？"

```
fw-AC63_BT_SDK/apps/hid/examples/keyboard/
├── app_keyboard.c          ← SDK入口，挂载GPS模块 + 按键转发
└── gps/                    ← GPS测速仪模块（全部自己写的）
    ├── drv_tm1638.c/h      ← LED驱动（GPIO位操作 + 段码表）
    ├── app_display.c/h     ← 显示管理（时间+速度+冒号+蓝牙指示灯）
    ├── gps_main.c/h        ← 主模块（按键处理+里程保存+模块集成）
    ├── nmea_parser.c/h     ← NMEA协议解析（状态机+校验）
    └── gps_uart.c/h        ← GPS UART接收（中断+滤波+里程积分）

修改的SDK文件：
├── board_ac6323a_demo_cfg.h  ← 板级配置（ADC按键端口+阈值+KEY_NUM）
└── board_ac6323a_demo.c      ← 板级初始化（ADC按键数据结构）
```

设计原则：SDK是主体，GPS模块是插件。不改SDK核心代码，只在3个扩展点插入：
1. `hidkey_app_start()` 末尾 → 调用 `gps_module_init()`
2. `sys_timer_add(100ms)` → 驱动 `gps_module_loop()`
3. `hidkey_app_key_deal_test()` → 转发到 `gps_key_event()`

## 六、关键数字（随口能说出来显得专业）

- 主控：AC6323A，32位RISC，48MHz，BLE 5.0 + EDR
- Flash：512KB，固件占约240KB
- LED：70颗独立LED拼成9位数码管 + 3组冒号 + 1个小数点
- CM4718：7个GRID，14字节RAM，三线串行1MHz
- GPS：AT6558R，9600bps，支持GPS+BDS双模
- 按键：8个ADC按键，22K上拉，PA8采样
- 刷新率：显示100ms刷新一次（10Hz）
- GPS更新：1Hz（每秒一次NMEA数据）
- 里程保存：30秒一次，VM系统，16KB空间
- 速度滤波：一阶低通，α=0.3，低速截断1km/h

## 七、电话功能实现 — 重点演示项

### "电话接听/挂断是怎么实现的？"

用BLE HID的Telephony Usage Page。在HID Report Map里定义了两个Collection：
- Report ID 1：Consumer Control（音量、播放、切歌）
- Report ID 3：Telephony（Hook Switch 接听/挂断）

Hook Switch是蓝牙HID标准定义的电话控制键，按一下接听，再按一下挂断，和有线耳机的线控按钮原理一样。iOS和Android都支持这个标准。

### "为什么不用HFP协议？"

HFP（Hands-Free Profile）是经典蓝牙的电话协议，需要建立SCO音频通道，复杂度高，而且我们这个设备不需要传输通话音频——音频还是走手机扬声器/耳机。我们只需要"接听"和"挂断"这两个控制动作，用BLE HID的Hook Switch就够了，更轻量。

### "MODE键的状态机逻辑是什么？"

MODE键根据电话状态做不同的事：

```
无电话时（s_phone_state=0）:
  单击 → 发 Consumer Control Play/Pause → 音乐暂停/播放
  双击 → 切换显示模式（速度→里程→最高速度）

来电时（s_phone_state=1）:
  单击 → 发 Telephony Hook Switch → 接听电话 → 状态变为"通话中"
  双击 → 发两次 Hook Switch（挂断+重拨）→ 回拨

通话中（s_phone_state=2）:
  单击 → 发 Telephony Hook Switch → 挂断电话 → 状态回到"无电话"
  双击 → 发两次 Hook Switch → 回拨
```

### "电话键和MODE键有什么区别？"

电话键更直接——不管当前状态，按一下就发一次Hook Switch。相当于"万能接听/挂断键"。MODE键则是智能的，无电话时按MODE是控制音乐，有电话时才变成电话控制。

### "电话状态怎么跟踪的？"

两个途径：
1. SDK蓝牙事件：如果手机通过经典蓝牙连接且支持HFP，SDK会收到 BT_STATUS_PHONE_INCOME（来电）、BT_STATUS_PHONE_ACTIVE（接通）、BT_STATUS_PHONE_HANGUP（挂断）事件
2. 按键操作推断：用户按接听键后状态从"来电"变"通话中"，按挂断键后变"无电话"

### "如果问到兼容性问题"

Hook Switch是USB HID和蓝牙HID的标准定义（Telephony Usage Page 0x0B, Usage 0x20），iOS从很早就支持，Android 5.0以上也支持。实测中如果某些手机不响应Hook Switch，备选方案是用Consumer Control的Play/Pause键，大部分手机在来电时按Play/Pause也能接听。

### HID Report Map技术细节（如果问得很深）

```
Telephony部分的Report Map:
  Usage Page (0x0B)     → Telephony设备
  Usage (0x01)          → Phone
  Report ID (3)         → 和Consumer Control的ID 1区分开
  Hook Switch (0x20)    → bit0, 1=按下 0=释放
  Phone Mute (0x2F)     → bit1, 预留
  padding 6 bits        → 凑满1字节
```

发送时：Report ID=3, 数据=0x01（按下Hook Switch），延时50ms，再发0x00（释放）。
